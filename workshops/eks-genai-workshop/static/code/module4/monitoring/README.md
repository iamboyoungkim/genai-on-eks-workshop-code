# Module 4: infrastructure monitoring manifests

English | [한국어](README.ko.md)

Manifests used by the Track A labs **A3 "Monitoring & Scaling"** and **A4 "Ray Serve autoscaling"**.

| File | What it deploys | Namespace |
|---|---|---|
| `neuron-monitor.yaml` | Neuron Monitor DaemonSet (NeuronCore metrics on `:8000`) on inf/trn nodes | `kube-system` |
| `adot-collector.yaml` | ADOT collector that scrapes vLLM + neuron-monitor and remote-writes to Amazon Managed Prometheus | `adot` |
| `grafana.yaml` | In-cluster Grafana with a pre-provisioned AMP data source (SigV4), served under `/app/` | `grafana` |
| `deploy-grafana.sh` | Deploys `grafana.yaml` with IAM role, Pod Identity association and a generated admin password | `grafana` |

`adot-collector.yaml` and `grafana.yaml` contain two placeholders that the lab fills in with `sed`:

- `__AMP_ENDPOINT__`: the AMP workspace `prometheusEndpoint` (ends with `/`)
- `__REGION__`: the AWS region

```bash
sed -e "s#__AMP_ENDPOINT__#${AMP_ENDPOINT}#" -e "s#__REGION__#${AWS_REGION}#" adot-collector.yaml | kubectl apply -f -
sed -e "s#__AMP_ENDPOINT__#${AMP_ENDPOINT}#" -e "s#__REGION__#${AWS_REGION}#" grafana.yaml | kubectl apply -f -
```

## AWS credentials (EKS Pod Identity)

| Service account | IAM role used in the lab | Managed policy |
|---|---|---|
| `adot/adot-collector` | `adot-collector-amp` | `AmazonPrometheusRemoteWriteAccess` |
| `grafana/grafana` | `grafana-amp-reader` | `AmazonPrometheusQueryAccess` |

EKS injects the Pod Identity environment variables (`AWS_CONTAINER_CREDENTIALS_FULL_URI`,
`AWS_CONTAINER_AUTHORIZATION_TOKEN_FILE`) only when a pod is **created**, and only if the association is already active.
A container restart (CrashLoopBackOff) does not pick it up; the pod must be recreated. A new association can also take a
few seconds to become effective, so a `rollout restart` issued right after `create-pod-identity-association` may still
produce a pod without credentials. The symptom in the ADOT logs is:

```
extensions::sigv4auth: could not retrieve credential provider: ... no EC2 IMDS role found
```

Recommended order (the association does not need the namespace or service account to exist yet):

```bash
aws eks create-pod-identity-association --cluster-name "$CLUSTER_NAME" \
  --namespace adot --service-account adot-collector \
  --role-arn "arn:aws:iam::${AWS_ACCOUNT_ID}:role/adot-collector-amp"
sleep 15
sed -e "s#__AMP_ENDPOINT__#${AMP_ENDPOINT}#" -e "s#__REGION__#${AWS_REGION}#" adot-collector.yaml | kubectl apply -f -
```

Check that the credentials were injected, and recreate the pod if they were not:

```bash
kubectl get pod -n adot -l app=adot-collector -o jsonpath='{.items[0].spec.containers[0].env[*].name}'; echo
kubectl rollout restart deployment/adot-collector -n adot   # only if AWS_CONTAINER_CREDENTIALS_FULL_URI is missing
```

The same applies to Grafana (`--namespace grafana --service-account grafana`).

## Grafana access

`./deploy-grafana.sh` does the whole Grafana setup in a safe order (IAM role, Pod Identity association, wait, admin
Secret, manifest, credential check). It needs `AMP_ENDPOINT`, `AWS_REGION` and `CLUSTER_NAME` from lab step 1 and is
safe to re-run.

Grafana is a ClusterIP Service served under the sub-path **`/app/`**, and is reached with a port-forward to local port
**8081**:

```bash
nohup kubectl port-forward -n grafana svc/grafana 8081:3000 >/tmp/grafana-pf.log 2>&1 &
```

| Where you run the browser | URL |
|---|---|
| Workshop Studio IDE (Code Editor behind CloudFront) | `https://<your-ide>.cloudfront.net/app/` |
| Local machine | `http://localhost:8081/app/` |

Why `/app/` on 8081: the IDE's nginx forwards `/app/...` unchanged to `localhost:8081/app/...`, while everything else
goes to the Code Editor. The Code Editor's own `/proxy/<port>/` route returns the Grafana HTML but not its static
assets, so Grafana shows "failed to load its application files" there.

Login: user `admin`, password from the `grafana-admin` Secret (generated by the script, there is no `admin/admin`
default):

```bash
kubectl get secret grafana-admin -n grafana -o jsonpath='{.data.GF_SECURITY_ADMIN_PASSWORD}' | base64 -d; echo
```

The Grafana HTTP API uses the same prefix. Lab commands that call `http://admin:admin@localhost:3000/api/...` (for
example the A4 Ray dashboard import) become:

```bash
GF_PW=$(kubectl get secret grafana-admin -n grafana -o jsonpath='{.data.GF_SECURITY_ADMIN_PASSWORD}' | base64 -d)
GRAFANA="http://admin:${GF_PW}@localhost:8081/app"
curl -s "$GRAFANA/api/datasources/uid/amp/health"
```

Security: the IDE `/app` route is **not** behind the IDE login, so while the port-forward runs anyone with the IDE URL
reaches the Grafana login page. Keep the generated password, and stop the port-forward when you are done
(`pkill -f "port-forward -n grafana"`). Do not add a LoadBalancer or Ingress for Grafana.

### Data source and dashboard queries

- Do not add a new data source. Use the pre-provisioned **Amazon Managed Prometheus** one (uid `amp`). The
  `http://localhost:9090` in the Prometheus server URL field is only a placeholder.
- One query row holds one PromQL expression. Panels with several expressions (P50/P95/P99) need one row per expression
  (**+ Add query**). Pasting several lines into one row fails with
  `parse error: unexpected identifier "histogram_quantile"`.
- Aggregate buckets across pods with `sum by (le)`:
  `histogram_quantile(0.95, sum by (le) (rate(vllm:e2e_request_latency_seconds_bucket[5m])))`

## Cleanup

```bash
pkill -f "port-forward -n grafana"
kubectl delete -f grafana.yaml --ignore-not-found   # also deletes the grafana-admin Secret with the namespace
kubectl delete -f adot-collector.yaml --ignore-not-found
kubectl delete -f neuron-monitor.yaml --ignore-not-found
```

The AMP workspace, IAM roles and Pod Identity associations are created with the AWS CLI in the lab and are not removed
by these commands.
